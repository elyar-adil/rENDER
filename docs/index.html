01 / Architecture

From a response
to a frame. All yours.

A web page does not arrive as pixels. rENDER works through the layers that turn a document into something you can see and interact with.

No borrowed engine hiding underneath. Every layer has a place.

The crates are separated by responsibility. The browser shell is the edge of the system; the document engine lives inside the repository.

02 / Under the hood

Small pieces.
One rendering system.

The engine is split into focused Rust crates. Each layer can be tested and improved without hiding missing work behind a different browser.

Documents & structure

HTML5 tokenization and tree construction, DOM mutation, namespaces, events and forms.

render-html · render-dom

Style & layout

Selectors, cascade, computed values and layout contexts including block, flex, grid and table.

render-css · render-layout

Pixels & presentation

JavaScript execution, display lists, image decoding, rasterization and retained compositing.

render-js · render-core
03 / Engineering principle

Standards over shortcuts.

A page that fails is evidence of a missing capability—not a reason to add a rule for that website. rENDER is developed against web standards, conformance suites and real-page diagnostics, with the engine itself responsible for getting better.

NO PER-SITE BRANCHES · NO EXTERNAL BROWSER FALLBACK
